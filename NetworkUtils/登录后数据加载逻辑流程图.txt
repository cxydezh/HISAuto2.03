核心函数调用关系
================

前端调用链：
用户登录成功 → 跳转到dashboard → DOMContentLoaded → 
├─ 初始化事件监听器
├─ loadPatientsByDepartment('personal') → 
│   ├─ fetch('/api/patients/{department}') → renderPatientList()
│   └─ 用户选择患者 → selectPatient() → 
│       ├─ loadPatientInfo() → fetch('/api/patient/{patient_id}') → renderPatientInfo()
│       └─ loadPatientAiResults() → fetch('/api/patient-ai-results/{patient_id}') → renderPatientAiResults()
│
├─ loadAiFunctions() → 
│   ├─ fetch('/api/ai-functions') → renderAiFunctions()
│   └─ 用户选择AI功能 → loadAiWorkflow() → fetch('/api/ai-workflow/{function_name}') → 
│       ├─ renderAiTree()
│       └─ renderAiDescription()
│
└─ 科室选择变化 → loadPatientsByDepartment(department)

后端调用链：
/api/patients/{department} → get_patients_by_department() [data_display.py]
/api/patient/{patient_id} → get_patient_info() [data_display.py]
/api/patient-ai-results/{patient_id} → db.get_patient_ai_results() [database.py]
/api/ai-functions → get_ai_functions() [data_display.py]
/api/ai-workflow/{function_name} → get_ai_workflow() [data_display.py]

数据流向
========

静态数据 (data_display.py):
├─ DEPARTMENTS: 科室列表
├─ PATIENTS_DATA: 患者数据（按科室分组）
└─ AI_FUNCTIONS: AI功能配置和工作流程

动态数据 (数据库):
├─ ai_run_results: AI运行结果表
└─ patients: 患者信息表

数据传递路径:
用户登录 → 页面初始化 → API请求 → 后端处理 → 数据返回 → 前端渲染

关键数据转换:
├─ 科室选择 → 患者列表过滤
├─ 患者选择 → 患者详细信息 + AI运行历史
└─ AI功能选择 → 工作流程配置 + 功能描述

数据加载时机:
├─ 页面加载时：科室患者列表 + AI功能列表
└─ 用户交互时：患者详情 + AI历史 + 工作流程

修改建议
========

1. 前端修改点:
   - dashboard.js 中的初始化逻辑
   - 数据加载函数的调用顺序
   - 用户交互事件的处理逻辑
   - 数据渲染和显示逻辑

2. 后端修改点:
   - app.py 中的API路由
   - data_display.py 中的数据结构
   - database.py 中的查询逻辑

3. 关键依赖关系:
   - 页面初始化依赖API数据加载
   - 用户交互依赖已加载的基础数据
   - 数据渲染依赖API返回的数据格式

4. 建议修改顺序:
   - 先修改数据结构和API接口
   - 再修改后端处理逻辑
   - 最后修改前端加载和显示逻辑

5. 性能优化建议:
   - 考虑数据预加载策略
   - 实现数据缓存机制
   - 优化API请求频率
