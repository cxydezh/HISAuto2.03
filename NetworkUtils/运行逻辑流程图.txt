核心函数调用关系
================

前端调用链：
用户点击"运行" 
    ↓
runAiFunction() 
    ↓
├─ 单项模式：runSingleAiFunction() 
│   ├─ fetch('/api/run-ai', POST)
│   └─ showWorkflowProgress()
│
└─ 组群模式：runGroupAiFunction()
    ├─ fetch('/api/patients/{department}')
    ├─ runAiForPatient()
    └─ fetch('/api/run-ai', POST)

后端调用链：
/api/run-ai (POST)
    ↓
├─ get_ai_workflow(function_name) [data_display.py]
├─ get_patient_info(patient_id) [data_display.py]
└─ db.save_ai_result() [database.py]

数据获取函数：
├─ get_departments() [data_display.py]
├─ get_patients_by_department(department) [data_display.py]
├─ get_ai_functions() [data_display.py]
└─ get_ai_workflow(function_name) [data_display.py]

数据流向
========

静态数据 (data_display.py):
├─ DEPARTMENTS: 科室列表
├─ PATIENTS_DATA: 患者数据
└─ AI_FUNCTIONS: AI功能配置

动态数据 (数据库):
├─ ai_run_results: AI运行结果表
└─ patients: 患者信息表

数据传递路径:
前端选择 → API请求 → 后端处理 → 数据库存储 → 结果返回 → 前端显示

关键数据转换:
├─ 患者选择 → patient_id → 患者详细信息
├─ AI功能选择 → function_name → 工作流程配置
└─ 运行结果 → JSON格式 → 数据库存储 → 历史记录显示

修改建议
========

1. 前端修改点:
   - dashboard.js 中的 runAiFunction() 函数
   - 单项/组群模式的处理逻辑
   - 进度显示和结果展示逻辑

2. 后端修改点:
   - app.py 中的 /api/run-ai 路由
   - data_display.py 中的AI功能配置
   - database.py 中的数据结构

3. 关键依赖关系:
   - 前端进度显示依赖后端返回的workflow数据
   - 数据库存储依赖后端生成的运行结果
   - 历史记录显示依赖数据库查询结果

4. 建议修改顺序:
   - 先修改数据结构和配置
   - 再修改后端处理逻辑
   - 最后修改前端显示逻辑
